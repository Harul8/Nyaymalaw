# NM Brain semantic hardening: implementation and qualified offline results

The fresh-response free-prose leaks are closed in the exercised public flows.
Every fresh displayed block now uses owned evidence expressions or code-rendered
outcomes, including explanations, questions, follow-ups and completion blocks.
A wrong accepting reviewer cannot restore writer-authored reply text or certify
an unsaved effect. Grounding, source-purpose and legal interpretation remain
semantic judgments: **four deliberately adversarial desired-rule cases still
fail** and remain explicitly open.

Production qualification freeze: `40c0a52ef4ba2f0959251843c10e89d468ba9615`.
The changes were committed and pushed in individually verified checkpoints to
`s0-foundations`. Documentation/archive commits after this freeze do not change
the production code tested here. Before Build LB-194–197 own the current work;
existing LB-175–193 preserve earlier requirements and evidence.

## What changed and what the user can inspect

| Review point | Implemented control | Practical limit |
| --- | --- | --- |
| False operational or factual prose disguised as an account, assessment or question | Closed fresh expression contract across every block kind; code resolves original attributed passages and checked legal expressions; independent review cannot alter rendering | Literal fidelity does not prove that a selected passage is relevant, adopted as fact or correctly applied |
| Reply claims completion without the requested effect | Completion and acknowledgement blocks remain code-owned regardless of links; a declared non-new mutation requires a typed outcome; relevant record tasks need matching checked effects | Initial request/target interpretation can still be semantically wrong |
| Correct work blocked by harmless bookkeeping | Normalize only declared empty/inapplicable metadata; retain exact consequential mismatch reasons and valid independent work | Populated contradictions and uncertain references remain errors |
| Same original message spans treated as unrelated authority | Canonical same-turn source links preserve their original identity and context; precise held scopes remain visible | Shared source identity is not permission to reinterpret another record |
| Source-purpose labels anchor the reviewer | Material and dispute reviewers read original evidence independently; exact substantive portions and support dependencies are checked; coverage records original-account dispositions | Classifier and reviewer can still make the same semantic mistake |
| Empty or partial extraction masquerades as complete review | Coverage binds representation to actually admitted support; held/rejected/unread proposals cannot fill gaps; earlier application/correction withdrawal and opening receipts are reconciled | A semantically incorrect coverage judgment is still possible |
| Internal repair consumes all remaining delivery capacity | One shared recovery budget reserves two of the eight conditional reservations for reply correction; source/coverage recovery stays bounded and preserves useful peers | This does not guarantee a model will produce useful content within that bound |
| Saved result differs from replayed result | Canonical JSON-compatible evidence snapshots preserve scope, coverage and exact reply bindings across atomic save/replay; rendering versions remain explicit | Historical accepted replies are not retrospectively certified by the new contract |
| Interpreter drafts effects before execution | `conversation.py` no longer asks for discarded reply/clarification wording; its closed schema owns routing and work selection; compatibility attributes remain empty | Routing still requires semantic interpretation of the original request |

The response construction tradeoff is deliberate: fresh output selects original
attributed evidence, checked legal propositions/passages and fixed questions,
proposed work and status templates. It has no arbitrary writer-prose escape
hatch. Browser-visible usefulness and complete legal deliverables still require
the deferred real-model evaluation; mechanical protection alone does not prove
that these constrained expressions satisfy every legal request.

## Remaining semantic defects and qualification boundaries

These are **desired-rule strict expected failures**, not passing demonstrations
of prevention. They expire if the desired admission outcome starts passing.

| Defect | Pressure case | Remaining failure |
| --- | --- | --- |
| B-177 | `material-20-wrong-date-false-judge-acceptance` | A deliberately wrong grounding ACCEPT can admit a false dated proposition despite owned exact source evidence |
| B-178 | `source-pressure-16-semantic-mislabel-false-rejection` | Wrong semantic purpose judgments can reject genuine account at the standalone classifier/grounding boundary |
| B-179 | `source-pressure-17-semantic-mislabel-false-admission` | A classifier and reviewer making the same wrong judgment can treat an unadopted draft as substantive account |
| B-180 | `source-pressure-18-instruction-only-mixed-false-admission` | A pure review instruction incorrectly treated as mixed account can receive fabricated positive substantive support |

B-178–180 are standalone purpose/admission probes; they do not, by themselves,
establish that an actual public turn escaped existing recovery or released a
false reply. The public source-owner reconsideration, coverage and peer-preserving
recovery cases test those handoffs separately. B-177 remains an admission defect;
closing arbitrary reply prose does not prove the underlying record is true.

Two additional positive guards remain **proposal-only qualification boundaries**:
B-181 (`extractor-14-wrong-fact-exact-source`) returns an untrusted false proposal
with an owned exact quote, and B-182 (`extractor-17-empty-is-proposal-only`) returns
a structurally valid empty envelope. Neither proves semantic correctness,
complete source coverage, a saved effect or released success. They must not be
counted as prevented failures merely because their characterization tests pass.

A further design risk is recorded in the standing instructions: future UI-only
enrichment must stay outside canonical durable records. A change to whole
projected-row display data must version its result catalogues, deltas, mutation
targets and seals together and preserve earlier reconstruction. **No new
canonical projection migration is implemented or qualified in this work.**

## Final qualification population

The final run is an explicit **165-module offline subset**, excluding journey,
Class D and PostgreSQL tests. It is not the whole repository suite. Its source
selection and local helper/import closure are archived with the exact collected
and executed node IDs and frozen hashes.

The final subset collected and executed **3,267 nodes: 3,241 passed, four strict
semantic expected failures and 22 failures**. No ordinary test was skipped or
reported as passing without a JUnit owner. All 22 failure identities match the
archived baseline: 21 current-plan-view tests and one prebuild-plan-link test.
There are no unmatched failure identities and no NM Brain failures in this
selection. The subset exits with failure; it is not a clean repository suite.
Identity matching does not itself re-verify every historical failure's cause.

The **232 distinct pressure cases** ran forward, reverse and shuffled with seed
20261008. Each order recorded **228 passes and four strict semantic expected
failures**: 684 passes and 12 expected failures across 696 executions. Expected
and observed outcomes, including fabricated outputs, stayed identical across
orders; all 98 pressure source pins matched the frozen commit and stayed intact.
Two of the 228 passes are proposal-only characterizations, leaving 226 passing
cases after that exclusion. Repeating orders adds no new scenarios and establishes
no population false-positive rate. First-round fabricated dispatches: 1,595.

The new application receipt slice was separately checked on 129 focused tests.
The routing-only slice passed 154 focused public/expression controls, plus separate
122-case routing/authority and 88-case public fixture selections. Their captured
logs/commands have narrower populations than this final subset and are not added
to its count. During qualification, tuple/list save drift and an early missing-
verification error-path change were found, fixed in `c4fb479`, and rerun before
this final freeze. The failed diagnostic remains checkpoint evidence rather than
being overwritten with a success claim.

The golden inputs remain twenty curated GS-06–25 scenarios, forty selected exact
passages and eight authored composites. They are not twenty acquired judgments
or authentic combined client files. Fabricated model outputs deliberately cover
correct, partial, malformed, hallucinated, empty, wrong-target and failed-effect
outcomes. Exact original passages, raw outputs, expectations, observations and
per-case accounting are retained in the evidence packet.

## Calls and prompt inventory

Against the named `611b1e8` implementation, this hardening adds no routine
model stage. This is not a comparison to `ea1253e`. Current scripted public
fixtures retain three calls for a greeting, eight for an ordinary correction and
zero new calls on exact replay. Conditional corrections and source/coverage
recovery use the existing turn-owned bound; provider attempts are accounted
separately. The older `ea1253e` comparison remains distinct: greeting 1→3 and
material path 7→8. Do not describe that historical increase as eliminated.

Static prompt inventory at the freeze is **15,189 words versus 15,746 at
`611b1e8`, a 3.54% reduction**. The writer prompt is 1,247 versus 2,371 words.
Method: AST top-level string constants whose names contain `SYSTEM` or
`APPENDIX`, whitespace word count, each reusable constant counted once.
Dynamic input, schema and recovery text are excluded. This differs from the
earlier reviewer's 15,365-word inventory and is not a live token/cost comparison.
No live cost, latency, semantic false-acceptance rate or false-rejection rate was
measured. **Real-model API calls: zero. Browser calls: zero.**
