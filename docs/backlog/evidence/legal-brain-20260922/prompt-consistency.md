# DG-17 — assembled instruction consistency

22 September 2026. Authorised after the read-only audit, then extended by the
owner's parallel legacy-prompt review. Status: implemented, scoped checks passed.

## Work and verification plan

1. Cross-dispute reads receive stable identities, readable labels and attributed
   current positions. Malformed/rejected findings cannot become an empty clean
   assessment. Test positive, foreign, duplicate-label and unavailable inputs.
2. Calendar resolutions require reproducible supplied-date/calendar arithmetic.
   Unsupported external-calendar expressions remain undated. Corrections require
   a separately quoted correction instruction; conflicting accounts remain live.
3. Proof unknowns remain unknown. Adverse propositions can be disputed or open
   with an attributed reason, without being conceded or falsely resolved.
4. Procedural roles cannot be approximated. Preserve explicit non-litigation
   states and the complete supplied account, with no implicit filed side.
5. Answer purpose controls presentation, never permissions or grounding. An
   explanation must not manufacture a recommendation or repeat a blocking ask.
6. Context can be reconsidered for a stated material reason. Remove predictive,
   optimistic and dismissive wording and concrete production-prompt examples.
7. Cover actual prompt construction sites, schema agreement, persistence and
   served answers. Run focused tests first, then affected browser regressions.

All tests use synthetic controlled inputs unless explicitly recorded otherwise.
No full Class-A, paid semantic evaluation or counsel acceptance is claimed here.

## Implemented mechanisms

- Cross-dispute prompts carry stable IDs and attributed substantive positions,
  not labels alone. Empty input, malformed output or foreign endpoints cannot
  produce a clean assessment. Private IDs are labelled before presentation;
  generated findings pass the normal grounding boundary rather than being
  exempted as engine disclosures. The controlled model uses the current format.
- Calendar dates must match reproducible supplied-date arithmetic. Unsupported
  calendar references, ambiguous numeric dates and wrong resolutions stay
  undated. Historical context cannot be admitted as a fresh date. Replacement
  needs a separately quoted current correction instruction and a known fact ID.
  The model still judges whether those words constitute a correction.
- Theory can account for disputed/unverified adverse propositions without
  conceding or pretending to resolve them. Reasons survive storage; malformed,
  overlapping or duplicate states are refused. Earlier reasoning errors can be
  corrected without inventing a changed fact.
- Explanation/assessment purpose reaches the answer, assembly and history.
  Completed explanation does not force an action or reopen the intake queue.
  Material blocks, grounding, permissions and limitation checks remain active.
  A contradictory explanation is withheld, not sent to a directive-step repair.
- Explicit non-contentious, unfiled and unsupported roles are distinct from an
  invented litigation role. The full supplied account reaches role interpretation.
  Explicit filing can progress an unfiled matter; inferred progression and
  reversal of an established side remain contested. Explicit non-filed matters
  can receive **limited source explanations**, not side-dependent recommendations.
- Recorded context is revisable for a stated material reason. Opposition is
  described conditionally, not predicted. No rescue is presumed. Necessary legal
  explanations are permitted; concrete production-prompt scenario examples and
  the `entry`/`fact_id` mismatch were removed.

## Additional legacy findings (DG-18)

The independent read-only pass traced schemas and wrappers, not just named system
constants. It found old instructions still active in structured-output fields:

1. Proof `closing_material` forced ABSENT when availability was unknown. Both the
   system instruction and wire description now preserve NOT_ASSESSED.
2. Factor `in_writing` collapsed unestablished form into oral-only and a negative
   limitation finding. True/false/null now distinguish written/oral/unestablished;
   a missing assessment or `cannot_tell` is not an empty negative result.
3. Issue extraction required a dispute/court question. It now covers relevant
   advisory and transactional questions without inventing an opponent.
4. Theory schema descriptions demanded relief for an unestablished theory and
   constrained revision reasons more tightly than the assembled prompt. Aligned.
5. Evidence inventory requested the wrong unknown token for holder; the prompt
   now uses each field's actual vocabulary. Embedded schema examples were removed.
6. The free-text advice repair skipped completion admission. It now uses the same
   refusal as the other legal-output paths for unfinished/unknown completions.
7. Unfiled-to-filed progression and the globally blocked explanation path were
   checked in consumers, not treated as fixed merely because new enums existed.

No extra system-prefix override was found in provider, policing/tracing,
composition, knowledge adapters or configuration. Historical diagnostic replay
requires its own explicit approval and is not a served-turn path. Stale explanatory
docstrings were clarified so they do not instruct a later maintainer to regress.
