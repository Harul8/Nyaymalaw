# Offline passage/output pressure test

This report preserves the original offline pressure-test baseline and records
the subsequent generalized repairs. The exercised mechanical checks constrain
ownership, requested effects, completion and persistence; **they do not prove
zero false claims or false rejections in unrestricted semantic work**. Before
Build remains the queue and status owner. Real-model/browser qualification
remains deferred by the user.

## Current integrated offline verification

At production HEAD `f021a5c`, **2,134 affected offline regression tests passed**;
three journey tests were deliberately deselected. This includes Brain readers,
independent reviewers, continuation, effects, saved state, historical replay,
model-port contracts, strict adapter quarantine and replay quarantine. The final
public-turn milestone and its JUnit evidence are in
[checkpoint 25](evidence/brain-gap-25-integrated-turn-recovery-20261006.json).

The final paired run covers **101 distinct cases in three orders: 303 passing
executions** with identical observed outcomes. The original 79 cases are joined
by 22 public source/omission recovery cases, including two-turn assignment
invalidation. The two direct ledger cases remain separate regression evidence;
they were not presented as invented user passages. Each pressure record is bound
to its actual executed pytest node. Successful public cases retain fabricated
outputs, the released reply and the reopened saved matter.

The [updated paired packet](evidence/brain-pressure-updated-20261006.json) records
511 fabricated dispatches in the first order, including setup and conditional
work. Normal supported turns and legitimate no-change reviews require no
semantic recovery dispatch. Conditional corrections and semantic recovery share
one configurable per-turn ledger, defaulting to eight reservations; provider
transport retries are separately counted. Failed pre-dispatch reservations
remain spent and cannot be attributed to a subsequent unrelated call.

Seven cases deliberately characterize remaining semantic dependencies,
including a false unrestricted reply accepted by an incorrect fabricated
reviewer. Their passing characterization assertions do **not** mean those
errors were prevented. Code-only acknowledgements have stronger effect/rendering
guarantees; mixed and unrestricted prose still depend on independent semantic
review. No real-model/API/browser calls were made, and no population false
acceptance/rejection rates were measured.

Ruff and whitespace checks passed. Repository dependency lint still reports
the existing `nm/brain/history.py:11` import of `nm.open_matter.transcripts_api`;
the file is byte-identical to starting commit `695c707`. The
[verification manifest](evidence/brain-pressure-updated-verification-20261006.json)

all-green repository or live semantic acceptance.

## Subsequent contract repairs

The repairs use declared work modes, exact owned references, typed disagreements,
completed provider receipts and checked coverage. Production does not recognize
example matter names, phrases or scenario IDs. The passage examples below remain
regression evidence, not implementation conditions.

| Earlier gap | General mechanism | Limit preserved |
| --- | --- | --- |
| False record-result prose alongside a truthful typed outcome | An explicitly interpreted pure record-acknowledgement mode renders exact selected record changes/current entries in code before response review, progress sealing and the atomic save. Rendering is versioned for durable replay. | Mixed requests and substantive follow-ups retain independent semantic review. A mode proposal cannot establish fulfillment or suppress another requested deliverable. |
| Harmless accepted-review metadata caused retries or withheld correct prose | Schema-declared unused empty arrays and empty/whitespace-only strings are canonicalized at strict transport and response-review boundaries; applicable generated shapes remain narrow. | Populated contradictions, unknown fields and ambiguous references remain errors. Normalization supplies no facts or permission. |
| Correcting one extractor unit erased an admissible sibling | Code-owned failed-unit IDs receive one keyed correction under exact declared operation/row choices. Sound proposals survive; independently checked completed rejected JSON can be quarantined at adapters/replay and revalidated per unit. Completed independent reviewer rows receive the same owner checks. | Retained extraction rows are proposals awaiting Judge admission. Incomplete/refused/ambiguous provider output is not salvageable, unknown envelopes remain unread, and missing coverage cannot become empty success. |
| Wrong source classification blocked a genuinely supported account | A structurally valid typed role disagreement triggers one candidate-free source-owner reconsideration over the complete original conversation. Changed roles invalidate dependent decisions and restoration peers; unaffected checked decisions retain their original owned IDs. | Reconsideration may legitimately remain unchanged or uncertain. The source owner receives no proposed fact, desired classification or approval reason; no keyword/reason-text trigger promotes content. |
| Independently detected omissions remained unrecovered | Exact owned missing-source IDs from valid partial coverage trigger one targeted extraction recovery pass, followed by independent review and whole-scope coverage assessment. Structural corrections and semantic recovery share the explicit turn-owned recovery ledger. | Unlocalized partial/unassessed coverage does not invent a target. Exhaustion preserves checked peers, marks remaining work unfinished and cannot reset a nested retry allowance. |

These controls add no routine model call solely for mechanical validation.
Recovery dispatches are conditional and separately counted from initial reads
and provider transport retries. A false classification or omission may require
additional source reading and independent review; count evidence does not
measure provider latency, tokens or cost.

A partial extraction receipt remains partial even if a later semantic reviewer
claims complete account coverage. Independently validated and admitted peers
can still produce truthful narrower effects; a full requested review cannot be
completed until its required reader and coverage obligations are satisfied.
The current salvage boundary requires at least one admissible proposal in a
partially read required stage. A wholly unread required stage with none prevents
commit/release, even if another reader has a checked peer. A fully checked empty
envelope remains a legitimate result. This boundary is not a promise of zero
false rejection.
The durable reply, selected effects, progress evidence and reopened record must
agree. A save failure releases no prepared saved/completed acknowledgement.

Empty admitted legal results can depend on rejected proposals and original
account purpose even though no accepted application premise remains. The
negative-cache freshness repair compares the existing original-read classified
scope with current exact source references and roles. It ignores local IDs,
reasons and newly added unrelated spans; unchanged scope remains reusable.
Without a narrower owned negative-dependency inventory, this scope comparison
is conservative and can reread an empty result after an irrelevant original
role change. A checked no-supplied-passages receipt remains account-independent;
legacy absent-catalogue compatibility supplies no new semantic guarantee.

The following counts and paired observations describe the **original baseline**.
They must not be read as current failure assertions or current implementation
qualification. Subsequent per-slice and integrated evidence is linked from the
owning Before Build rows and the dated `brain-gap-*` evidence packets.

## Original transport and continuing semantic limits

Source and extraction tests distinguish permissive transport followed by actual
Brain validation from strict adapter rejection using production `require_schema`.
In the original strict-rejection baseline, Brain received no rejected object;
correction preserved the original input but `rejected_output` was `None`. The
subsequent opt-in quarantine contract changes that completed-object handoff;
it does not make a rejected provider object an accepted fact. Material-verification tests
use strict whole-envelope schema validation. Public-release tests use the
explicit offline/legacy transport, with live-shaped metadata cases; they do not
qualify real provider transport behavior.

Scripted correct rejection proves wiring, not that a real reviewer recognises
the error. Scripted incorrect acceptance demonstrates the consequence of a
wrong semantic decision. Exact quotation and owned IDs do not establish meaning.
No measured false-positive/false-negative rate, semantic accuracy or exhaustive
legal correctness follows from these runs. Real-model/browser qualification
remains deliberately deferred by the user.

  remain unverified. Mock pass counts and gate-fire counts are not these rates.
