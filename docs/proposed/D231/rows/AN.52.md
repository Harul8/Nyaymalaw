## Description

THE OWNER'S WORDS, 12 Nov 2026: "Also translate all the updates you suggested in forensic review into the build plan". The review itself was asked for on 11 Nov 2026: "You are doing a forensic review of Nyaymalaw, a legal research assistant for Indian advocates that is about to be hosted for other advocates ... report what you find". The review document is FORENSIC_REVIEW.md in the review copy (commit 03e95289; not in the repository); F-numbers below are its findings, and its section 6 is the order followed here. WHAT THE REVIEW FOUND. D176 plans a server that stops itself when quiet, a wake page, a reranking machine started on demand and a 50 dollar budget. It assumes behaviour the code does not yet have: health always answers 'ready'; a failed reranking continues the research on first-stage results; nothing measures 'quiet' and stopping the worker cuts every running step; secrets, the key and the year-long log sit in the code folder.
DECISIONS. D207-D215 are Claude's proposals from the review, recorded at the owner's instruction; for the owner to correct before each piece is built. A finding marked CONFIRMED was read by two readers or shown by a script; PLAUSIBLE was read and not proven end to end (column 7).
D207 (F-11, High). READINESS IS MEASURED, NOT STATED. One owner of readiness performs a cheap real act for each capability (the store opens and a key unwraps; an index answers one query; the reranker scores one pair; the malware scanner answers; mail and the model account are reachable) and reports each as ready, not ready or not checked. The start-up check fails on 'not ready'. The public health answer says up or down only; the detail is behind sign-in, and no longer names the provider, the model or the code's fingerprints.
D208 (F-10, High for hosting). 'UNAVAILABLE' STOPS THE RESEARCH; IT IS NEVER A FALLBACK. The reranker sits behind one port with a local and a remote adapter. A reranker or vector model that cannot be used is a typed failure with its cause stored, and the research step stops with a plain reason, recorded as not assessed, to be continued when it is back. The same rule for every degraded stage.
D209 (F-12, High). QUIET IS MEASURED AND A STOP IS ORDERLY. One activity ledger that every long activity registers with (a step waiting or working, a paper being scanned or read, dictation, a voice note, a save). The idle timer reads only that ledger and the time of the last signed-in action. An orderly stop takes no new steps, waits for those working up to a limit, then exits. At the next start a recorded step is let go only after the advocate's sign-in is checked, and is kept where the sign-in has lapsed.
D210 (F-16, High). NM KNOWS WHY RESEARCH IS NOT AVAILABLE. One state owned by NM (available, starting, paused by the budget, unavailable), set from the typed answer to the start request and said at the stop in code's words, so that 'paused by the budget' is never retried as 'no capacity'. The wake page is behind a check only enrolled advocates pass. A second, absolute AWS budget stops everything. FOR THE OWNER: the review also proposed a ceiling on what one turn may spend; P16 says the product has no spending cap, so that is the owner's decision and is not built here.
D211 (F-15, High). SECRETS AND THE KEY LIVE APART FROM THE DATA. Settings and secrets are fetched at start from a parameter store by the server's own role. The store, the key and the outgoing-data log are on named paths outside the code folder. Volumes are encrypted. Snapshots are of the data volume only, and the key is never on it. The credentials an agent on the laptop holds are named with their limits.
D212 (F-14, High for hosting). THE PROVIDER'S WAIT IS HONOURED. A rate-limit refusal is retried after the wait the provider states, within a capped total, and the process limits how many provider requests it sends at once.
D213 (F-19). A STOP OR STEER THE PAGE WAS TOLD HAD NOT LANDED DOES NOT LAND LATER. The web process marks a request it stopped waiting for as withdrawn; the worker ignores withdrawn requests and clears requests at its start.
D214 (F-20). A STEER SAID TO BE 'TAKEN' IS SAVED FIRST, beside the conversation, so a restart before the next model call does not lose the advocate's correction.
D215 (F-31). NM'S OWN REJECTED REQUEST IS NOT AN OUTAGE. A provider answer that NM's request was malformed, unauthorised or named an unknown model is a configuration or programming fault: it stops the turn with a service notice and its diagnostics, and is not caught by the handlers that treat a model error as 'try again' (defect shape S10). An abandoned and retried request records the cost of every attempt that may be billed.

D237 (the question 52a2 left under D207). THE START MEASURES, AND REFUSES WHERE NM IS NOT READY. Before the server takes a request it measures readiness (52a1) and refuses to start, naming each capability that is not ready with why. WHY, for a legal application: a server that starts without its library, its store or its record of what it sends takes an advocate's message and fails it part-way, and leaves an advocate to find out from an answer what the operator should have been told at the start. 'Not checked' never refuses: nothing was learned. THE COST, said: the start waits as long as the search models take to load (they were warmed in the background), and a missing malware scanner refuses the start although papers are held safely without one. So there is ONE switch, the operator's: NM_START_UNREADY=serve starts at once, measures in the background and prints what is not ready when it is known; it is said at every start that uses it, and the public health answer stays 'down' until NM is ready. It is the setting for development; a hosted server does not set it.
D238 (52b: the exception AN.48's register needs for D208). RECOMMENDED: GRANT IT. A reranker or vector model that cannot be used should stop the research step as not assessed, never give a ranked-looking result from the first stage. For a legal application this is the direction that matters: an answer whose authorities were chosen without the reranker looks exactly like one chosen with it. NOT BUILT, and why: it changes retrieval.py and research.py, which D143 pins, and the plan's own proof for a change inside pinned code is the recorded replay (D151) - a paid run on an amount the owner names, which cannot be made from the cloud container (it holds no provider key). So the exception is recorded as recommended; its entry in the register, its diff, its pin update and its proof are for a session that can run the replay.
D239 (D210's question: a ceiling on what one turn may spend). RECOMMENDED: NO CEILING THAT STOPS AN ANSWER; P16 STANDS. A ceiling that cuts off a legal answer part-way is itself a harm: the advocate cannot tell what a stopped-for-cost answer left out. What already bounds a turn: three attempts a call, each step's allowance of corrections (D150), the provider's own usage limit, which NM already takes as a stop with Continue (P51), and the account's absolute budget on the provider's and the host's side (D210). Nothing is built for this. The rest of D210 (NM knowing why research is not available; the wake page) waits for 48f7's design, as before.
