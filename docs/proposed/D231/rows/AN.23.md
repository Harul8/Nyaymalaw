# AN.23 - Build: Conversation history in pages of ten, with a kept line per saved file (P35, O29)

## ID

AN.23

## Item

Build: Conversation history in pages of ten, with a kept line per saved file (P35, O29)

## Description

SEES: Conversation history opens with its first ten items - conversations first, then earlier matter records, each newest first, as now - and a Load more button that adds the next ten, until none remain; the line above the list keeps its totals and says how many are shown of how many ('Showing 10 of 75'). THE SERVER: GET /api/work and /api/chats take limit and offset (without them they answer the whole list, as before) and answer the page with has_more and next_offset; the totals count only the signed-in advocate's items. A KEPT LINE: for each saved file, one small record - owner, first message and turn count, or title - derived once per version of the file (its write time and size) and kept sealed in a sibling folder (history-lines), under the matter's own key, or the installation seal for an older record that has no key of its own, exactly as the file itself is sealed; a history call reads these lines and opens a large file only when its line is missing or its file has changed. Only readable, checked lines are kept; a line whose file cannot be read, or whose receipts fail the checks, is derived afresh each time. The line is derived again after each answer (in the background, after the answer has gone) and for every file when the server starts (in the background), so the first call after either finds it ready. MUST NEVER: show or count another account's item; show an unreadable list as an empty one; list an item twice or skip one (the page drops a repeated id; the server's order is fixed); open a file's content to build a line when a line for its current version is kept; use a line for a file that has changed; keep any client words unsealed; fail a request because a line could not be kept. WHEN IT FAILS: the rows already shown stay and a message offers to try again. DEPENDENT WORK, NOT BUILT: erasure (P2, not built) must remove a file's line with it. PIECES: the store's two port methods and their implementation; the route's use of kept lines; the route's pages; the background derivations; the page's rows and button; the button's style; each with focused tests. PASS: the offline tests pass, a cold call on the owner's store reads lines and opens no large file, and the owner sees ten rows at once. FAILURE SCOPE: the history list. RECOVERY: revert the commits; the kept lines are derived data and can be deleted.
