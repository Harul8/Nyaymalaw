DECISIONS. D187-D194 are Claude's proposals from the review, recorded at the owner's instruction; for the owner to correct before each piece is built. A finding marked CONFIRMED was read by two readers or shown by a script; PLAUSIBLE was read and not proven end to end (column 7).
D187 (F-08, High). THE SAVE LOCK IS RELEASED WHEN ITS PROCESS DIES. The lock of a matter's save becomes an operating-system lock on the lock file, the mechanism the account claim already uses (store_directory.py:557-577), so a killed server leaves nothing behind. One mechanism: no start-up sweeper is added beside it.
D188 (F-07, High). A SAVE THAT LOST A RACE IS 'NOT SAVED', NOT 'UNKNOWN'. Where the store refuses the save as stale and a clean reload does not hold the answer, the outcome is known: the answer is kept, re-based on the conversation as it now stands, and saved on Continue with no model call. 'Unconfirmed' is kept only for a reload that itself fails, and that state gets an owner: the next request for that message looks in the store and settles it as finished or retryable, so no message is refused for ever.
D189 (F-07, the trigger). NOTHING WRITES BESIDE THE CONVERSATION ONCE THE FINAL SAVE BEGINS. The title's late write is shut out with the turn's own progress writer before the final save, or waits for it.
D190 (F-01, Critical). THE KEY ROTATION CANNOT LEAVE A STORE UNREADABLE. One inventory of everything the secret seals, read by both the backup and the rotation (the matters, the key records, and what else is sealed under it: AI-sharing permission, pending accounts, reset links, the mail outbox, the steps handed to the worker). The whole store root is backed up. The new secret is written to its file before the first change. New key records are written beside the old and swapped only after every one is verified. The command refuses to run while a server or worker is alive on the store, handles an interruption like any other failure, and says 'restored' only of what it restored.
D191 (F-13, High for hosting). AN OLDER COPY IS NOTICED. A small index, written inside the same lock as the save, holds each matter's last saved version and a hash of its sealed file; a file below it is refused or shown as rolled back, never loaded as current. The backup is documented as stop, then copy; a restore drill exists as a test.
D192 (F-17). ONE OWNER OF THE STEPS AT A TIME. The process that works the steps holds one exclusive operating-system lock for its life, taken before its start-up recovery; a second refuses to start.
D193 (F-34). A MATTER FILE SAYS ITS FORMAT. The sealed file's format number is checked on opening, and a saved field the running code does not know is refused or carried through unchanged, never dropped, so rolled-back code cannot silently strip a matter saved by newer code (P46).
D194 (F-36, and a Low item). THE PUBLISHING RENAME IS DURABLE. On Linux the folder is flushed after the rename; on Windows a rename refused because a reader holds the file is retried for a bounded moment; a crash between creating a new matter's key file and writing it no longer blocks that identifier.
D247 (15 Nov 2026, D191 AMENDED to what was built, under the owner's word to go with Claude's recommendations and to complete what was pending). THE RECORD OF THE LAST SAVE HOLDS A HASH OF WHAT WAS SAVED, NOT OF THE SEALED FILE. Sealing is not deterministic: the same matter sealed twice gives different bytes, and a file sealed again with its matter unchanged - a record from before sealing, sealed on its next save, or a matter given a new data key - would otherwise read as another file at the recorded version and be refused. What was saved is what the record vouches for. A hash of a whole conversation, with its own identifiers and times, confirms nothing to anyone who does not already hold it.
D248 (15 Nov 2026, D193 CONFIRMED as built, as D247). A SAVED FIELD THE RUNNING CODE DOES NOT KNOW IS REFUSED, NOT CARRIED THROUGH. D193 allowed either. Refusing keeps code from writing back a record it cannot read whole; a newer format is opened by the code that wrote it, as a rolled-back database refuses a newer file. Carrying fields through unread is not built.
