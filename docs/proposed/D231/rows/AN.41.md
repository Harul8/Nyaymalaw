## Description

THE OWNER'S WORDS, 4 Nov 2026, after a message sent with 8 files stopped part-way and was not in the history: "as soon as a message is sent, attachments are sent - they should be saved to history first and then processed further, so that no work is ever lost"
Claude proposed saving first, and asked whether being signed out should stop an answer. THE OWNER'S WORDS, 4 Nov 2026: "30 mins of idle time, where user didn't do anything and NM is also not doing thing and hence idle for 30 mins"; on picking up exactly where a message stopped: "plan this"; "does it take so much time? wouldn't it show any response or progress at all during that time? tell me how do we make this stream responses, so that at least there is some progress - thoughts only, no code change"
Claude proposed one mechanism - each step's result saved as it finishes - for no work lost, for continuing and for the progress, a suggested order of building, and a "Continue" button on a stopped message. THE OWNER'S WORDS, 4 Nov 2026: "no button, this should be through a message -- when response is stopped in between, lets send a message saying so in red font and then may be a give a button there it self, continue , discrad buttons, instead of persiting button elsewhere -- record everything in the build plan under Suggested order"

DECISIONS (agreed 4 Nov 2026), in the suggested order of building:
D65. Signed out for being idle (F-A-12) only after 30 minutes in which neither the advocate nor NM does anything: from Send until the answer is saved or stops, the advocate counts as active, on the page and on the server alike, and the 30 minutes start once NM has finished. The twelve-hour limit of a sign-in is unchanged.

STEP 1 - THE SERVER'S OWN SLOWNESS (first: the cheapest gain, and it changes nothing NM writes). Each time a part of the answer is shown, the whole answer is drawn again from scratch with nothing reused (measured in Notes): draw only what is new, or reuse within the turn what the drawing derives. The rest of the time in which no AI call is running is found by a free timing of the turn's own steps on a copy, and mended piece by piece, each piece recorded here with its measurement.

STEP 2 - NOTHING LOST.
D66. When Send is pressed, the message and its files are saved into the conversation before any AI work begins; the conversation is in the history from that moment, its message shown as being worked on.
D67. Each step's result is saved, sealed with the conversation, the moment the step finishes: NM's understanding of the matter (its disputes and legal questions), the research for each dispute, the questions asked and the answers given (as now, AN.37), the case for each dispute, each section once it passes its check, the check across the sections, and the overview. Today only the sections that passed are kept - on the 4 Nov message, from about 25 minutes in.

STEP 3 - THE WORK SHOWN AS IT GOES.
D68. Not the AI's words as it writes them: every part of an answer is checked (exact quotations, sources, the independent review) before the advocate sees it. What is shown is the work, read from the saved steps as each finishes: about a minute in, the disputes and legal questions NM found, a short line each, so that a misunderstanding can be corrected early; for each dispute as its research finishes, the Acts, sections and judgments chosen, opening in the reading pane as today; the matter board filling dispute by dispute; for each section "written - being checked", then "the check asked for N corrections - rewriting", then the section itself; then the check across the sections and the overview. The status line read every 2 seconds stays. It is read from the saved conversation, so it survives a reload and is as private as the answer. The matter board's and the reading pane's UI and structure are unchanged (D60).

STEP 4 - AN ANSWER THAT STOPPED, AND CONTINUING.
D69. When an answer stops part-way, whatever the cause (a restart, a sign-out, the twelve-hour limit, AI data sharing turned off, the allowance used up, a service failure), NM says so in the conversation itself, in a message in red, in code's own words: why it stopped, what is finished and what is not; with Continue and Discard buttons in that message. No button anywhere else (owner: "instead of persiting button elsewhere").
D70. Continue picks the answer up where it stopped: each saved step is checked as a saved answer is checked, and kept where it passes; only what is missing, or a step that stopped halfway, is run again. A saved step is redone, never patched, where another message has been sent in the conversation since, the law it relied on has changed, or it cannot be read reliably. Where the cause must be put right first (AI data sharing off, the allowance used up) the red message says so, and Continue works once it is.
D71. Discard (its meaning proposed by Claude, for the owner to confirm): the unfinished answer is removed from the conversation; the advocate's message and files stay. Where a new message is sent instead of either button, the buttons go and what was finished is saved as a stopped answer, as today (P27). An answer that stopped is saved as final only when it finishes, is discarded or the advocate moves on, so a saved answer is still never reworked (P46).

OPEN, for the owner: (a) sections shown as drafts marked "being checked" before their check passes - Claude advises against (the advocate might read what the check then removes); not built unless the owner asks. (b) Whether NM continues by itself after a server restart, the message having been sent already - Claude's earlier suggestion; until the owner says, every stop waits for Continue.
THE OWNER'S WORDS, 4 Nov 2026, on the three open points. On Discard: "it just takes off the notification and the continue, discrad options -- unifinished work is saved as is -- users can give furthere steps through chat messages and NM acts accordingly". On drafts: "no need to share drafts, just the completed work, but like I sadi earlier, show the work in pieces as they are done instead of waiting for everything to be done". On NM continuing by itself after a server restart: "yes".
DECISIONS (agreed 4 Nov 2026):
D71 (REPLACED - this text supersedes D71 above). Discard takes off the red message and its Continue and Discard buttons, and nothing else: the unfinished work stays in the conversation, saved as it is (a stopped answer, P27), and the advocate gives any further steps as messages in the conversation, which NM acts on as on any message. Sending a new message instead of pressing either button does the same. A saved answer is still never reworked (P46): Continue finishes an answer that stopped; after Discard or a new message it stays as it stopped.
D72. No drafts: only completed work is shown, each piece as soon as it is done rather than once everything is done (D68; P26). Closes open point (a).
D73. After a server restart NM continues by itself an answer that was being worked on, the message having been sent already. The red message with Continue and Discard appears only where it cannot continue by itself (the sign-in ended, AI data sharing turned off, the allowance used up, or the continuing itself failed). Closes open point (b). Claude's proposal within it, for the owner to see in the browser: a one-line note in the conversation that the answer was interrupted by a restart and continued.
