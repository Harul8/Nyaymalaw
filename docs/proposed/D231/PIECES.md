D231 stage 1 (17 Nov 2026): one line a piece, made from the sheet by plan_export.py. Proposed for the owner to accept, change or refuse; until then the sheet stays the one work queue (P7).

Closed list: Applied; Partly applied; Built, not applied; Built, where it runs not recorded; Agreed, not built; Done without a build; For the owner; Not classified.

A row with commits - those it cites, and those whose message names it, leaving out commits that change only the plan workbook - is classed by git: all of them in the code the running server was started on (2abeb974) -> Applied; some -> Partly applied; none -> Built, not applied. Otherwise the status is proposed by a rule from the words the plan writes in capitals in the row's Status: APPLIED anywhere -> Applied; else BUILT -> Built, where it runs not recorded; else FOR THE OWNER alone -> For the owner; else AGREED, PLANNED or DECIDED -> Agreed, not built; else DONE, ANALYSED, CHECKED or MEASURED -> Done without a build; else Not classified. The rule cannot tell a piece applied or built in whole from one in part, nor see a later piece left open: the words column shows what the row says, in order, and the row itself is the record.
