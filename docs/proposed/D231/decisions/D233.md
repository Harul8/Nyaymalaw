## From [AN.49](../rows/AN.49.md), Description

D233 (13 Nov 2026; 49d as it is built, Claude's proposal under D181, for the owner to correct before it is applied). THE GATHERED FORM IS VERSION 3 OF THE CASE STEP (core_case_v3), in nm/core_engine/case_strength.py alone. Both calls - the account and its check - give the account in one gathered shape, so no call is added: the headings of the model's own choosing, as many as the dispute needs; each element as before, with the number of its heading; each thing the other side will rely on as before, with the number of the heading it attacks (0 where it attacks none); each thing to get from one person or place, with the numbers of every element it serves; and the few things that most decide the dispute as the papers stand, each with the numbers of the elements and of the other side's points it concerns. CODE'S CHECKS, mechanical, made again exactly on replay: an element whose heading number names no heading is put under code's own heading 'Other things the law requires', and said so - never dropped; a heading no element sits under is not shown; an attack that names no heading is kept as attacking none; an ask's numbers that name no element, or an element the papers already show, are taken off it, and an ask left serving none is set aside, as v2 sets one aside; a deciding item's numbers that name nothing are taken off and its words kept. NOTHING LOST: the record also keeps the first call's account, and code notes in the record each element of it whose words are not among the checked account's elements. Whether that note is shown to the advocate, and how an element reworded is told from one taken out, is for the paid check (point (b)) to measure first. WHAT THE PAGES READ: each thing to get keeps 'for' (the first element it serves), so what is built today reads it as before, and adds 'serves' (every element it serves). A case saved as v1 or v2 is read, checked and shown exactly as saved (P46). What the board, the pane and the note draw of a v3 case is 49e, 49f and a note piece of its own, applied with 49d and not before.

## From [AN.49](../rows/AN.49.md), Description

D233 asked each point of the other side for the number of the heading it attacks. Measured on three disputes: the first call gave heading numbers; the check call, in all three, gave the numbers of requirements instead, so that code set 10 of 15 points down as attacking nothing and read the other 5 against whatever heading happened to bear that number. The model's own reading is the more exact one - a point of the other side attacks a requirement, not a heading - and the asks and the deciding items already name requirements by number. So: each point names the requirements it attacks, as an ask names those it serves; code keeps the ones that are in the list and reads the heading from the first of them; a number that names no requirement is taken off and noted. What the note and the board read (the heading a point goes against) is unchanged in form.
