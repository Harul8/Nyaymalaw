# D237

Written out from the Advocate build plan by plan_export.py; the sheet is the record (P7).

## From [AN.52](../rows/AN.52.md), Description

D237 (the question 52a2 left under D207). THE START MEASURES, AND REFUSES WHERE NM IS NOT READY. Before the server takes a request it measures readiness (52a1) and refuses to start, naming each capability that is not ready with why. WHY, for a legal application: a server that starts without its library, its store or its record of what it sends takes an advocate's message and fails it part-way, and leaves an advocate to find out from an answer what the operator should have been told at the start. 'Not checked' never refuses: nothing was learned. THE COST, said: the start waits as long as the search models take to load (they were warmed in the background), and a missing malware scanner refuses the start although papers are held safely without one. So there is ONE switch, the operator's: NM_START_UNREADY=serve starts at once, measures in the background and prints what is not ready when it is known; it is said at every start that uses it, and the public health answer stays 'down' until NM is ready. It is the setting for development; a hosted server does not set it.
