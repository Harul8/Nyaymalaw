# D242

Written out from the Advocate build plan by plan_export.py; the sheet is the record (P7).

## From [AN.52](../rows/AN.52.md), Description

D242 (THE OWNER'S CORRECTION OF D237, 13 Nov 2026). Asked "should the server refuse to start when something is not ready, or print what is not ready and go on?", the owner answered: "print and go on". So D237 is turned about: THE START SAYS WHAT IS NOT READY AND GOES ON. The server starts at once, measures readiness on a thread of its own, and prints a line for each capability that is not ready, with why, when it is known; it serves all the same. What D237 built is kept as the operator's choice and no longer the rule: NM_START_UNREADY=refuse makes the start measure first and refuse where NM is not ready, for an installation that wants that. A value of that setting that is neither 'refuse' nor 'serve' refuses the start and says so - a mistyped 'refuse' must not quietly serve. UNCHANGED: the check command still fails on what is not ready (52a2), and the public health answer still says 'down' while a capability is measured not ready (52a3) - so on a computer with no malware scanner the server runs and that one address says down.
